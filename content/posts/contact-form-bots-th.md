วันที่ 13 พฤศจิกายน 2026 easycms.dev มีปุ่มติดต่อที่มุมขวาล่าง เบื้องหลังไม่ใช่บริการฟอร์มของใคร แต่เป็น plugin form builder ของ Easy CMS ตัวเดียวกับที่ใครก็ติดตั้งได้ รันอยู่ในหน้า admin ของเว็บเอง บนฐานข้อมูลของเว็บเอง

ฟอร์มสาธารณะคือประตูที่เปิดทิ้งไว้ และผู้มาเยือนกลุ่มแรกแทบไม่เคยเป็นคน บทความนี้เล่าว่า form builder ตัดสินอย่างไรว่าใครผ่านได้: ด่านที่เปิดอยู่เสมอ ด่านที่เพิ่มได้ ข้อมูลที่เก็บ วิธีที่ข้อความเก่าถูกลบ และส่วนที่ผมยังแก้ไม่ได้

## form builder ในหนึ่งนาที

`@easy-cms/plugin-form-builder` เพิ่มเมนู **ฟอร์ม** ในหน้า admin ผู้แก้เนื้อหาต่อฟอร์มจาก block (ข้อความ ข้อความยาว อีเมล ตัวเลข เบอร์โทร ตัวเลือก checkbox วันที่ และข้อความคั่นระหว่างช่อง) เลือกว่าหลังส่งจะเกิดอะไร และใครจะได้อีเมล หน้าเว็บแสดงฟอร์มด้วย element ตัวเดียว หรือจะ render เองจาก API ก็ได้

```ts
import { consoleEmail, defineConfig } from '@easy-cms/core'
import { formBuilderPlugin } from '@easy-cms/plugin-form-builder'

export default defineConfig({
  // …
  email: consoleEmail(), // หรือ smtp() จาก @easy-cms/email-smtp
  plugins: [formBuilderPlugin({ defaultTo: 'hello@example.com' })],
})
```

```html
<script type="module" src="/api/cms/form/element.js"></script>
<easy-form form="contact"></easy-form>
```

plugin เพิ่มสอง collection คือ `forms` กับ `form-submissions` จึงต้องสร้าง migration (`easy-cms migrate:create forms`) ฟอร์มมีฉบับร่าง และรับข้อมูลได้เฉพาะฟอร์มที่เผยแพร่แล้ว

ส่วนที่ผมสนใจในบทความนี้คือสิทธิ์ของ collection ข้อมูลที่ส่งมา ผู้ใช้ที่ล็อกอินอ่านได้ เฉพาะ admin ลบได้ และไม่มีใครสร้างหรือแก้ผ่าน REST API ได้เลย ข้อมูลที่ส่งมาเกิดได้ทางเดียวคือ endpoint ของฟอร์มเอง `POST <api>/form/:slug/submit` หลังผ่านทุกด่านข้างล่าง

## ข้อมูลหนึ่งชิ้นต้องผ่านอะไรบ้าง

![ด่านที่ข้อมูลจากฟอร์มต้องผ่านตามลำดับ: honeypot, ตรวจค่าในช่อง, token จับเวลาที่เซ็นไว้, Cloudflare Turnstile ถ้าตั้งไว้ และ rate limit บอทที่ติดด่านแรกและด่านที่สามได้คำขอบคุณปลอม ด่านอื่นได้ข้อความ error ส่วนข้อมูลที่ผ่านจะถูกเก็บโดยไม่มี IP แจ้งเป็น form.submitted ส่งอีเมล และลบข้อมูลเก่า](/images/blog/contact-form-bots/diagram-1.th.png)

ลำดับมีผล จึงขอเล่าตามที่ endpoint ทำจริง

**1. honeypot** ทุกฟอร์มมีช่องซ่อนที่ชื่อแบบที่บอทชอบกรอก คือ `website` หรือ `homepage` หรือ `url_address` ถ้าฟอร์มใช้ชื่อนั้นอยู่แล้ว คนมองไม่เห็นช่องนี้ มันอยู่นอกจอ มี `aria-hidden`, `tabindex="-1"` และ `autocomplete="off"` โปรแกรมอ่านหน้าจอและคีย์บอร์ดจึงข้ามไปด้วย ถ้าช่องนี้มีค่ากลับมา แปลว่าเป็นบอท

**2. ค่าในช่อง** ต่อมาตรวจค่ากับฟอร์ม: ช่องที่ต้องกรอก อีเมลที่หน้าตาเป็นอีเมล ตัวเลขในช่วง `min` และ `max` ตัวเลือกที่อยู่ในรายการ และความยาว (ช่องข้อความ 1,000 ตัวอักษร ข้อความยาว 10,000) เก็บเฉพาะช่องของฟอร์ม อย่างอื่นใน body ทิ้งหมด error ของแต่ละช่องตอบกลับเป็น 400 ด่านนี้มาก่อนด่านจับเวลาโดยตั้งใจ คนที่ลืมกรอกช่องไหนต้องได้รู้ ไม่ว่าจะกรอกเร็วหรือช้า

**3. token จับเวลา** ตอนหน้าเว็บโหลดฟอร์ม `GET <api>/form/:slug` คืน token รูปแบบ `<time>.<signature>` ที่เซ็นด้วย secret ของ CMS แล้วตอนส่งก็แนบกลับมา token ที่อายุไม่ถึง 2 วินาที (`minSubmitSeconds`) แปลว่าไม่มีใครอ่านฟอร์ม ส่วน token ที่ตรวจลายเซ็นไม่ผ่าน หรืออายุเกิน 24 ชั่วโมง จะได้ข้อความ "ฟอร์มหมดอายุ โปรดโหลดหน้าใหม่แล้วลองอีกครั้ง"

**4. Cloudflare Turnstile ถ้าเปิดไว้** เซิร์ฟเวอร์ส่งคำตอบ Turnstile ของผู้เข้าชมไปที่ endpoint `siteverify` ของ Cloudflare และรอไม่เกิน 10 วินาที

**5. rate limit** ส่งได้ไม่เกิน 5 ครั้งต่อผู้เข้าชมต่อฟอร์มใน 10 นาที (`rateLimit: { max: 5, window: 600 }`) เกินจากนั้นได้ 429 กับข้อความ "ส่งบ่อยเกินไป โปรดรอสักครู่แล้วลองใหม่"

ผ่านหมดแล้วจึงเก็บข้อมูล plugin แจ้ง event `form.submitted` เข้าคิวอีเมล และถ้าตั้ง `retentionDays` ไว้ ก็ลบข้อมูลเก่า ผู้เข้าชมเห็นข้อความขอบคุณของฟอร์ม หรือถูกพาไปหน้าอื่น

## โกหกบอทโดยตั้งใจ

ดูด่าน 1 กับ 3 อีกครั้ง บอทที่กรอก honeypot หรือส่งเร็วกว่าที่คนทำได้ จะไม่ได้ error แต่ได้คำตอบแบบเดียวกับคนทุกอย่าง คือ `{ confirmation }` พร้อมข้อความขอบคุณของฟอร์ม โดยไม่มีอะไรถูกเก็บและไม่มีอีเมลออกไป

comment ในโค้ดบอกเหตุผลไว้: บอทได้คำตอบเดียวกับคน มันจะได้ไม่รู้ว่าโดนจับ error คือสัญญาณ สคริปต์ที่ได้ 400 เพราะกรอก `website` จะเลิกกรอก `website` ส่วนสคริปต์ที่ได้คำขอบคุณไม่มีเหตุผลต้องเปลี่ยนอะไร

ข้อแลกเปลี่ยนมีจริง และผมต้องยอมรับมันเอง คนที่ส่งภายใน 2 วินาที เช่น ใช้เบราว์เซอร์ที่กรอกทุกช่องให้ทีเดียวแล้วกดส่งเร็ว จะได้คำว่า "ขอบคุณ" แต่ข้อความหายไป ผมเลือก 2 วินาทีเพราะอย่างน้อยคนต้องอ่าน label ก่อน และปรับขึ้นลงได้ด้วย `minSubmitSeconds` แต่การทิ้งแบบเงียบๆ คือความล้มเหลวที่แย่ที่สุดสำหรับคนคนเดียวที่โดน และผมยังไม่มีวิธีแยกเขาออกจากบอทที่ก็มาเร็วเหมือนกัน

ด่านที่คนอาจพลาดเองได้ (ลืมกรอก หน้าหมดอายุ Turnstile และ rate limit) ตอบเป็น error จริงทั้งหมด เพราะคนต้องรู้ว่าต้องทำอะไรต่อ

## rate limit ที่ไม่เก็บ IP

rate limit ต่อผู้เข้าชมต้องรู้ว่าผู้เข้าชมคือใคร และบนฟอร์มสาธารณะสิ่งเดียวที่มีคือ IP address แต่ form builder สัญญาไว้ว่าเก็บข้อมูลโดยไม่มี IP และผมไม่อยากมีตาราง IP แอบอยู่ข้างๆ

key จึงเป็น hash ทุกครั้งที่ส่ง plugin คำนวณ HMAC ด้วย secret ของ CMS จาก IP ฟอร์ม และช่วงเวลาปัจจุบัน แล้วเก็บ 32 ตัวแรกไว้ใน field ซ่อนชื่อ `rateKey` ของข้อมูลชิ้นนั้น ไม่มีใครอ่าน field นี้ผ่าน API ได้ และไม่เคยแสดงที่ไหน ตอนตรวจ limit ก็นับข้อมูลของฟอร์มนั้นใน 10 นาทีล่าสุดที่ key ตรงกับช่วงเวลาปัจจุบันหรือช่วงก่อนหน้า

เพราะช่วงเวลาอยู่ใน hash key จึงเปลี่ยนทุก 10 นาที ข้อความสองชิ้นจาก IP เดียวกันที่ห่างกันหนึ่งชั่วโมงมี key ที่ไม่เกี่ยวกันเลย จึงเอา key ที่เก็บไว้มาโยงข้อความของคนคนเดียวข้ามเวลาไม่ได้ และถ้าไม่มี secret ก็ย้อน key กลับเป็น IP ไม่ได้

ทั้งหมดนี้ต้องให้เซิร์ฟเวอร์รู้ IP จริงของผู้เข้าชม ถ้าอยู่หลัง proxy ที่ไว้ใจได้ให้ตั้ง `trustProxy` (Vercel กับ Netlify รู้จักให้อัตโนมัติ) ถ้าเซิร์ฟเวอร์ไม่รู้ IP เลย ผู้เข้าชมทุกคนจะใช้ limit ร่วมกันหนึ่งก้อนที่ใหญ่เป็นสิบเท่าของ `max` และเซิร์ฟเวอร์เตือนใน log หนึ่งครั้ง ทางสำรองนี้เกิดจากความผิดพลาด ซึ่งจะเล่าข้างล่าง

## Turnstile เฉพาะเมื่อขอ

ด่านในตัวหยุดสคริปต์ง่ายๆ ได้ แต่สคริปต์ที่โหลดหน้า รอสักสองสามวินาที และไม่แตะช่องซ่อน ก็ผ่านไปได้ สำหรับกรณีนั้น plugin เพิ่ม [Cloudflare Turnstile](https://developers.cloudflare.com/turnstile/) ได้ ซึ่งเป็นการตรวจที่ส่วนใหญ่ไม่ต้องคลิกอะไร:

```ts
formBuilderPlugin({
  turnstile: {
    siteKey: process.env.TURNSTILE_SITE_KEY,
    secretKey: process.env.TURNSTILE_SECRET_KEY,
  },
})
```

site key ออกไปพร้อมฟอร์ม (`form.turnstile`) แล้ว `<easy-form>` จึงโหลด script ของ Cloudflare แบบ `render=explicit` และวาด widget ลงในฟอร์มตอนนั้น ถ้าไม่มี site key ก็ไม่โหลด script ของ Cloudflare เลย ถ้าเว็บมี Content Security Policy ให้เพิ่ม `https://challenges.cloudflare.com` ใน `script-src` และ `frame-src`

ฝั่งเซิร์ฟเวอร์ การตรวจนี้ล้มแบบปิด ไม่มีคำตอบ network error หรือ Cloudflare ไม่ตอบใน 10 วินาที นับเป็น "ไม่ผ่าน" ทั้งหมด และผู้เข้าชมได้ข้อความ "ยืนยันว่าไม่ใช่บอทไม่สำเร็จ โปรดลองอีกครั้ง" ผมยอมเสียข้อความไปตอน Cloudflare ล่มดีกว่ารับทุกอย่างในช่วงนั้น จากนั้น element ก็โหลดฟอร์มใหม่ ได้ token ใหม่และ challenge ใหม่

Turnstile เป็นด่านเดียวที่ส่งข้อมูลของผู้เข้าชมไปให้คนอื่น จึงปิดไว้จนกว่าจะตั้งค่า และหน้าความเป็นส่วนตัวของ easycms.dev ก็เขียนถึงมันไว้

ด่านเหล่านี้ไม่ได้มีไว้แค่ฟอร์ม ตั้งแต่ 0.46.0 token ชื่อ honeypot, rate key และ `verifyTurnstile` ย้ายไปอยู่ใน core แล้ว และการสมัครสมาชิกเว็บ (site members) ก็ผ่าน token กับ Turnstile ชุดเดียวกัน

## ข้อความไปที่ไหน

ข้อมูลที่เก็บมีค่าที่กรอก หน้าที่ส่งมา และภาษา ในหน้า admin แถบข้างของฟอร์มบอกจำนวนข้อมูลที่ส่งมาและ export เป็น CSV ได้ โดยใส่ byte-order mark ให้ Excel อ่านภาษาไทยออก และ escape ช่องที่ขึ้นต้นด้วย `=`, `+`, `-` หรือ `@` เพื่อไม่ให้ spreadsheet รันเป็นสูตร

แล้วก็ต้องมีคนรู้:

- **อีเมล** แต่ละฟอร์มมีรายการอีเมลที่ส่งทุกครั้งที่มีคนกรอก ใช้ `{{name}}` แทนค่าของช่อง และ `{{*}}` แทนทุกช่อง "ตอบกลับถึง" ใส่ `{{email}}` ได้ กดตอบแล้วถึงคนส่งเลย
- **อีเมลยืนยันถึงผู้ส่ง** อีเมลที่ "ถึง" เป็น `{{email}}` ไปหาใครก็ได้ที่กรอกฟอร์ม แปลว่าใครก็สั่งให้เว็บส่งอีเมลไปที่อยู่ไหนก็ได้ อีเมลแบบนี้จึงใส่ได้แค่ช่องสั้น (ไม่มีข้อความยาว ไม่มี `{{*}}`) และตัดที่ 100 ตัวอักษร ไม่อย่างนั้นฟอร์มจะกลายเป็นช่องส่งสแปมฟรีในนามโดเมนของคุณ
- **Telegram** ตั้งแต่ 1.32.0 plugin ส่ง `form.submitted` และ `@easy-cms/plugin-notify` แปลงเป็นข้อความ Telegram บอกชื่อฟอร์มกับคนส่ง แต่ไม่บอกคำตอบ เพราะอาจเป็นข้อมูลส่วนตัว จึงให้อ่านในหน้า admin
- **Webhook** event เดียวกัน หรือ webhook ที่ฟัง create ของ `form-submissions` ส่งข้อมูลแต่ละชิ้นไปที่ระบบไหนก็ได้

อีเมลออกผ่าน email adapter ที่ตั้งไว้ เข้าคิวในฐานข้อมูลและลองส่งใหม่ถ้าส่งไม่สำเร็จ

## ลบข้อความเก่า และมันทำงานจริงอย่างไร

ฟอร์มติดต่อเก็บข้อมูลส่วนบุคคล และวิธีที่ซื่อตรงคือเก็บแค่ช่วงเวลาหนึ่ง `retentionDays: 365` ลบข้อมูลที่เก่ากว่าหนึ่งปี

ขอเล่าให้ตรงว่ามันทำอะไร เพราะชื่อ option สัญญาไว้มากกว่าโค้ดนิดหนึ่ง ไม่มี job ตั้งเวลา ตอนท้ายของการส่งที่สำเร็จแต่ละครั้ง plugin หาข้อมูลที่เก่ากว่า `retentionDays` แล้วลบทีละไม่เกิน 50 ชิ้น ข้อความเก่าจึงหายไปเมื่อมีข้อความใหม่เข้ามา ฟอร์มที่ไม่มีใครส่งเลยจะเก็บของเก่าไว้เกินกำหนดจนกว่าจะมีคนส่ง และค่านี้ใช้กับข้อมูลของทุกฟอร์มพร้อมกัน ตั้งแยกรายฟอร์มไม่ได้

สำหรับฟอร์มติดต่อที่มีข้อความเข้ามาเรื่อยๆ แบบนี้ใกล้เคียงกับ "ลบหลังหนึ่งปี" พอ แต่สำหรับฟอร์มที่เงียบไป มันไม่ใช่ และนี่คือข้อแรกในรายการข้างล่าง

## easycms.dev: ปุ่มติดต่อ

ปุ่มบน easycms.dev เป็นการทดสอบที่ดี เพราะไม่ได้ใช้ `<easy-form>` เลย เว็บเป็น Next.js และอยากได้หน้าตาของตัวเอง (แผงที่มีลิงก์ไป docs และ GitHub discussions ก่อน กับคำแนะนำให้เปิด GitHub issue ถ้าเป็นบั๊ก) จึง render ฟอร์มเองด้วย client ของ plugin:

```ts
import { getForm, submitForm } from '@easy-cms/plugin-form-builder/client'

const form = await getForm('contact', { api: '/api/cms', locale: null })

const result = await submitForm(
  'contact',
  {
    data: { kind, message, email, name },
    token: form.token,
    page: location.pathname,
    locale: null,
    ...(form.turnstile ? { turnstile: turnstileToken } : {}),
    [form.honeypot]: honeypotValue,
  },
  { api: '/api/cms' },
)
```

ใน component นั้นมีการตัดสินใจไม่กี่อย่างที่น่าเอาไปใช้:

- **ไม่โหลดอะไรจนกว่าจะมีคนคลิก** ฟอร์ม (และ token) ถูกโหลดตอนเปิดแผงครั้งแรก ส่วน script ของ Cloudflare โหลดเฉพาะตอนแผงเปิดอยู่และฟอร์มตอบกลับมาพร้อม site key ผู้เข้าชมที่ไม่เคยคลิกจะไม่โหลดทั้งฟอร์มและ Turnstile
- **วาดช่อง honeypot เอง** ไว้นอกจอ มี `aria-hidden`, `tabIndex={-1}` และ `autoComplete="off"` ใช้ชื่อที่ API ให้มา ฟอร์มที่ทำเองแล้วลืมช่องนี้ก็ยังใช้ได้ แต่เสียด่านนี้ไป
- **400 ที่ไม่มี error รายช่องจะโหลด token ใหม่** นั่นคือกรณี "ฟอร์มหมดอายุ" ที่มีคนเปิดแท็บค้างไว้ทั้งวัน เขาเห็นข้อความแล้วส่งใหม่ได้โดยไม่ต้องรีโหลดหน้า

ฝั่งเซิร์ฟเวอร์ config ของเว็บเปิด Turnstile เฉพาะเมื่อมี key ครบทั้งสองตัวใน environment และเก็บข้อความไว้หนึ่งปี:

```ts
formBuilderPlugin({
  retentionDays: 365,
  ...(process.env.TURNSTILE_SITE_KEY && process.env.TURNSTILE_SECRET_KEY
    ? { turnstile: { siteKey: process.env.TURNSTILE_SITE_KEY, secretKey: process.env.TURNSTILE_SECRET_KEY } }
    : {}),
}),
notifyPlugin(),
```

ตอนรันในเครื่องและใน preview ที่ไม่มี key ฟอร์มก็ใช้ได้ด้วยด่านในตัวอย่างเดียว ไม่มีใครต้องปลอมบัญชี Cloudflare

ตัวฟอร์มสร้างด้วยสคริปต์ seed: ช่อง "ประเภท" ที่ต้องเลือกจากห้าค่า คำถามที่ต้องกรอก อีเมลที่ต้องกรอก และชื่อที่ไม่บังคับ ช่อง "ถึง" ของอีเมลเว้นว่างไว้ให้ admin กรอก ใน repository จึงไม่มีที่อยู่อีเมล การ render ฟอร์มเองมีข้อเสียอยู่ข้อหนึ่ง: ชื่อช่องและค่าของตัวเลือกอยู่สองที่ คือฟอร์มในฐานข้อมูลกับ component ที่ส่งค่า สคริปต์ seed จึงเขียน comment ไว้ว่าผู้แก้เนื้อหาเปลี่ยนข้อความและอีเมลในหน้า admin ได้ แต่ห้ามเปลี่ยนชื่อช่องหรือค่าของประเภท

สุดท้าย [หน้าความเป็นส่วนตัว](/th/privacy) ของเว็บบอกไว้ในย่อหน้าเดียวว่าฟอร์มเก็บอะไร (ประเภท คำถาม อีเมล ชื่อถ้ากรอก และหน้าที่ส่งมา) ไม่เก็บ IP ลบข้อความหลัง 365 วัน ผู้ดูแลได้รับแจ้งทางอีเมลและ Telegram และ Cloudflare ตรวจผู้ส่งเมื่อเปิด Turnstile ย่อหน้านั้นเขียนง่าย เพราะทุกประโยคตรงกับ config หนึ่งบรรทัด

## อะไรที่พังระหว่างทาง

บั๊กสามตัวจาก changelog แก้แล้วทั้งหมด และเป็นแบบที่โผล่เฉพาะนอก test suite:

- **0.20.1 วันเดียวกับที่ออกครั้งแรก** `<easy-form>` อ่าน `form`, `api` และ `locale` จาก attribute อย่างเดียว แต่ Vue กับ React ตั้งค่าเป็น *property* ของ custom element ที่มี property นั้น `<easy-form :locale="locale">` ใน Vue จึงถูกเมินแบบเงียบๆ ตอนนี้ element รับได้ทั้งสองแบบ
- **0.65.0** ฟอร์มที่เซิร์ฟเวอร์ไม่รู้ IP ของ client ไม่มี rate limit เลย ตอนนี้ผู้เข้าชมกลุ่มนั้นใช้ limit ร่วมกันที่สิบเท่าของ `max` และเซิร์ฟเวอร์เตือนหนึ่งครั้ง คุณจะได้รู้ว่าต้องตั้ง `trustProxy`
- **0.68.2** package ประกาศว่าไม่มี side effect ทำให้ Vite และ bundler อื่นตัด `import '@easy-cms/plugin-form-builder/element'` ทิ้งตอน build production และ `<easy-form>` ว่างเปล่า dev server ไม่ tree-shake จึงไม่มีใครเห็น ตอนนี้ package ระบุ element กับ CSS ของมันเป็น side effect แล้ว

## อะไรที่ยังขาด

- **การลบข้อมูลเก่าควรมีตารางเวลา** ควรรันเป็น job ไม่ใช่รอข้อความถัดไป และตั้งแยกรายฟอร์มได้
- **ไม่ได้ดูเนื้อหา** ทุกด่านดูว่าฟอร์มถูกส่งมาอย่างไร ไม่เคยดูว่าเขียนอะไร คน หรือสคริปต์ที่เก่งพอ ยังส่งข้อความเต็มไปด้วยลิงก์ได้
- **คนที่เร็วมากโดนทิ้งเงียบๆ** เล่าเหตุผลไปแล้วข้างบน ผมอยากมีทางให้คนจริงได้ลองอีกครั้งโดยไม่สอนอะไรบอท แต่ยังไม่มี
- **มีผู้ให้บริการเดียว** Turnstile เป็นการตรวจภายนอกตัวเดียวที่มีในตัว ถ้าอยากใช้เจ้าอื่นตอนนี้ต้องเพิ่ม option เอง

form builder เป็นส่วนหนึ่งของสิ่งที่ระดับ 4 ใน roadmap เรียกว่า business engine คู่กับร้านค้าและหลายเว็บใน CMS เดียว ผมเขียนเรื่องระดับต่างๆ ไว้ใน [Easy CMS ไม่ใช่แค่ CMS](/th/blog/more-than-a-cms-th)
