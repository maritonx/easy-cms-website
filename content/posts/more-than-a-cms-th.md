Easy CMS เริ่มจากไอเดียเดียว: headless CMS ที่อยู่ในแอป Nuxt หรือ Next.js ของคุณเอง โครงสร้างเนื้อหาเป็น TypeScript ใน repository หน้าแอดมินอยู่ที่ `/admin` และไม่ต้องรัน server ตัวที่สอง วันนี้ก็ยังเป็นแบบนั้น และยังเป็นสิ่งแรกที่คนส่วนใหญ่ใช้

แต่พอถึงช่วงเวอร์ชัน 1.40 ผมเริ่มรู้สึกว่าคำว่า "CMS" ไม่ได้บอกแล้วว่ามันสร้างอะไรได้บ้าง มันมีระบบล็อกอินและบทบาท มีไฟล์บน S3 มีคิวงานที่ลองใหม่เองได้ มีร้านค้า ฟอร์ม webhook มี AI ที่เขียน alt text ให้ และรันหลายเว็บในการติดตั้งเดียว ของแบบนี้ไม่ใช่ที่เก็บบทความบล็อกแล้ว มันคือ backend เกือบทั้งก้อน

บทความนี้จึงเล่าว่า Easy CMS กำลังจะไปทางไหน และผมทำอย่างไรให้คำสัญญานั้นตรงกับของจริง

## ไฟล์ TypeScript ไฟล์เดียว ได้ backend ทั้งก้อน

สิ่งที่ทำให้ไปทางนี้ได้มีมาตั้งแต่ commit แรกเมื่อ 25 กันยายน 2026: ทุกอย่างเริ่มจาก config TypeScript ไฟล์เดียว

```ts
export default defineConfig({
  collections: [
    {
      slug: 'orders',
      access: { read: ({ user }) => (user?.role === 'staff' ? true : { customer: { equals: user?.id } }) },
      realtime: true,
      fields: [
        { name: 'customer', type: 'relationship', to: 'users' },
        { name: 'total', type: 'number', access: { update: ({ user }) => user?.role === 'admin' } },
        { name: 'status', type: 'select', options: ['new', 'paid', 'shipped'] },
      ],
    },
  ],
})
```

จากไฟล์นี้คุณได้ตารางในฐานข้อมูลพร้อม migration, type ที่ query คืนกลับมา, REST API, หน้าแอดมิน และกฎสิทธิ์ชุดเดียวที่ทุกทางเข้าต้องผ่าน กฎข้างบนที่ว่าลูกค้าอ่านได้เฉพาะคำสั่งซื้อของตัวเอง ใช้กับหน้าแอดมิน, REST, Local API ในโค้ดฝั่ง server, API key, stream แบบ realtime และ AI agent ที่คุยกับ MCP server เขียนครั้งเดียวจบ

ข้อสุดท้ายนี่แหละคือหัวใจ backend ส่วนใหญ่คือกฎว่าใครทำอะไรได้ ถ้ากฎอยู่ที่เดียว การเพิ่มทางเข้าใหม่ ไม่ว่าจะเป็น stream, agent หรือ webhook ก็ไม่ต้องเขียนกฎซ้ำแล้วภาวนาให้มันตรงกัน

## หกระดับ

เพื่อบอกว่า Easy CMS จะไปทางไหนโดยไม่สัญญาสิ่งที่ยังไม่มี ผมเขียนมันเป็นหกระดับ จากสิ่งที่มันเคยเป็น ไปจนถึงที่ที่ผมอยากให้มันไปถึง แต่ละระดับมีรายการ "ใช้ได้วันนี้" และ "ยังต้องทำ" หน้า [roadmap](/th/roadmap) แสดงรายการเดียวกันนี้ และแก้จากหน้าแอดมินของ Easy CMS ที่เว็บใช้อยู่เอง

![หกระดับของ roadmap ของ Easy CMS: ระดับ 1 ถึง 3 ครบแล้ว ระดับ 4 กำลังทำต่อ ระดับ 5 และ 6 อยู่ระหว่างทาง แต่ละระดับบอกสิ่งที่ใช้ได้วันนี้และสิ่งที่ยังต้องทำ](/images/blog/more-than-a-cms/diagram-1.th.png)

**1. Headless CMS ครบแล้ว** collection และ global, ฉบับร่างและเวอร์ชัน, ตั้งเวลาเผยแพร่, เนื้อหาไทยและอังกฤษพร้อมสถานะการแปล, คลังสื่อ, live preview, REST และ GraphQL จุดเริ่มต้นของทุกอย่าง

**2. Backend as a service ครบแล้ว** SQLite, Turso และ Postgres พร้อม migration ที่ commit ไว้ รหัสผ่าน single sign-on และสมาชิกของเว็บ ไฟล์บน S3, Cloudflare R2 และ Vercel Blob รันบน Node.js, Bun, Deno และ Cloudflare Workers โดยทดสอบทุก pull request และตั้งแต่ 1.47.0 มี realtime: แอปของคุณ subscribe การเปลี่ยนแปลงของ collection ผ่าน Server-Sent Events โดยกรองด้วยกฎสิทธิ์ชุดเดียวกัน นี่คือชิ้นสุดท้ายที่ขาด และทำให้ระดับนี้ครบ

**3. App framework ครบแล้ว** config และ Local API ที่มี type, hook และกฎสิทธิ์ในโค้ด, บทบาทที่ละเอียดถึงระดับ field และ action ที่กดจากปุ่มในหน้าแอดมินแล้วรันโค้ดฝั่ง server ของคุณ ทั้งใน Next.js และ Nuxt

**4. Business engine กำลังทำต่อ** วันนี้ใช้ได้แล้ว: plugin ร้านค้า (ยังเป็น preview), หลายเว็บใน CMS เดียว, ตัวสร้างฟอร์ม, มุมมองที่บันทึกไว้ และมุมมองปฏิทิน ถัดไปคือมุมมอง Kanban และ template CRM กับระบบจองสำหรับ `create-easy-cms`

**5. Durable workflows อยู่ระหว่างทาง** คิวงานในฐานข้อมูลของคุณเอง พร้อมการลองใหม่ ตารางเวลา และ outbox สำหรับ webhook และอีเมล ที่ยังขาดคือ workflow หลายขั้นที่รอได้หลายวัน และทำต่อได้หลังระบบล่ม

**6. AI-native อยู่ระหว่างทาง** plugin AI สำหรับ Claude, GPT และ Gemini พร้อมโควตารายวัน, MCP server (preview), API key ที่ไม่มีวันได้สิทธิ์เกินผู้ใช้เจ้าของ และ audit log ที่ลงลายเซ็น ที่ยังต้องทำ: เอา MCP ออกจาก preview และให้การแก้ไขของ agent รอคนอนุมัติก่อน

สามจากหก วันนี้อยู่ตรงนั้น และหน้า roadmap ก็บอกตามนั้น

## "ครบ" แปลว่าอะไร

กฎที่ผมใช้กับตัวเองสั้นมาก: ระดับหนึ่งจะครบเมื่อสิ่งที่ระดับนั้นต้องมีออกแล้ว และ CI ทดสอบมันทุก pull request ไม่ใช่แค่มีโค้ด และไม่ใช่แค่ทำงานได้บนเครื่องผม

ระดับ 2 เป็นตัวอย่างที่ดี เพราะเป็นระดับล่าสุดที่ครบ ในเวอร์ชัน 1.47.0 เดือนพฤศจิกายน 2026 realtime ออกแบบในที่เปิดก่อน ([ADR-0070](https://github.com/maritonx/easy-cms/blob/main/docs/adr/0070-realtime.md)): connection SSE เส้นเดียวรับได้หลาย subscription, ตาราง event ที่เขียนใน transaction เดียวกับการบันทึก จึงไม่มีการประกาศสิ่งที่ไม่ได้เกิดขึ้นจริง, ต่อกลับด้วย `Last-Event-ID` และกรองตามสิทธิ์ของผู้รับแต่ละคน จากนั้นจึงสร้าง แล้วตามด้วยเทส: integration test บน SQLite และบน Postgres จริง, เทสที่รัน CMS สอง instance แล้วการบันทึกที่ตัวหนึ่งต้องไปถึงผู้รับที่อีกตัว, end-to-end test ที่หน้าเว็บของผู้เยี่ยมชมต้องเปลี่ยนตามเมื่อบรรณาธิการเผยแพร่ในอีกหน้าต่าง และ smoke test บน Cloudflare Workers

การรีวิวยังจับปัญหาหนึ่งได้ก่อนออกเวอร์ชัน ผู้รับที่กรองบทความตามหมวดหมู่ได้รับ event ว่าบทความ "ออกจาก" มุมมองของเขาตอนมีคนแก้ไข แม้เขาจะไม่เคยมีสิทธิ์เห็นบทความนั้นเลย event นั้นมี id ของบทความติดไปด้วย จึงเท่ากับบอกว่ามีเอกสารที่ซ่อนอยู่ ทางแก้คือส่ง `leave` และ `delete` ให้เฉพาะผู้รับที่เห็นเอกสารนั้นได้ก่อนการเปลี่ยนแปลง หลังจากทั้งหมดนี้แล้ว ระดับ 2 บน roadmap จึงเปลี่ยนจาก "กำลังทำต่อ" เป็น "ครบแล้ว"

roadmap ยังตั้งใจไม่ใส่บางอย่างด้วย ไม่มีเปอร์เซ็นต์ เพราะ "ระดับ 4 เสร็จไป 60%" ไม่ใช่สิ่งที่ใครตรวจได้ ไม่มีวันที่ของระดับที่กำลังทำ มีแค่ชิ้นถัดไปหนึ่งหรือสองชิ้น และไม่เทียบ Easy CMS กับใคร มันบอกแค่ว่า Easy CMS ทำอะไรได้

## ยอดเขา: คนกับ agent ใต้กฎชุดเดียวกัน

ระดับ 6 คือเหตุผลของการไต่ทั้งหมด จึงควรพูดให้ชัดว่าหมายถึงอะไร

การแก้เนื้อหาของเว็บจะถูกร่างโดย AI agent มากขึ้นเรื่อยๆ ทั้งคำอธิบายสินค้า งานแปล หรือการแก้ลิงก์เสียห้าสิบจุด คำถามไม่ใช่ว่า agent เรียก API ได้ไหม เพราะได้อยู่แล้ว คำถามคือมันทำภายใต้กฎอะไร

ใน Easy CMS agent ต่อเข้า MCP server ด้วย API key คีย์นั้นเป็นของผู้ใช้คนหนึ่ง และไม่มีทางทำได้มากกว่าที่บทบาทของผู้ใช้คนนั้นทำได้ แถมยังจำกัดให้แคบลงได้อีก เช่น "อ่านและสร้างบทความเท่านั้น" agent ต้องผ่านกฎสิทธิ์ชุดเดียวกันทีละ field เหมือนที่คนผ่านในหน้าแอดมิน ทุกการเปลี่ยนแปลงลงใน audit log และแต่ละรายการลงลายเซ็นไว้ รายการไหนถูกแก้ทีหลังจะตรวจลายเซ็นไม่ผ่าน

ที่ยังขาดคือขั้นตรงกลาง ที่ยอดเขา agent ร่างการเปลี่ยนแปลง คนเห็นแล้วกดอนุมัติ และ audit log บันทึกทั้งสองอย่าง ว่าใครเสนอและใครตอบตกลง นั่นคือรายการ "การแก้ไขของ agent ที่รอคนอนุมัติ" ในระดับ 6 ซึ่งยังไม่ได้สร้าง เมื่อสร้างเสร็จ backend ที่คุณเขียนในไฟล์ TypeScript ไฟล์เดียวจะเป็นที่ที่คนกับ agent ทำงานด้วยกัน โดยไม่มีใครข้ามกฎได้

## ทำไมทุกระดับเป็น MIT

ทุกระดับระหว่างทางออกใน release ที่เป็น MIT ไม่มีแผนเสียเงินที่ roadmap ค่อยๆ พาไป และไม่มีอะไรที่ติดป้าย "ใช้ได้วันนี้" ที่ต้องใช้ license key Easy CMS รันบน infrastructure ของคุณ บนฐานข้อมูลของคุณ

ผมคิดว่าเรื่องนี้สำคัญกับ backend ยิ่งกว่ากับ CMS เพราะคุณเอาผู้ใช้ คำสั่งซื้อ และกฎของธุรกิจไปไว้ในนั้น คุณควรอ่านได้ทั้งหมด รันได้ทั้งหมด และย้ายออกไปพร้อมทุกอย่างได้

## เริ่มจากตรงไหน

ไม่ต้องรอถึงระดับ 6 ทุกอย่างข้างบนที่บอกว่า "ครบแล้ว" หรือ "ใช้ได้วันนี้" อยู่ใน release ปัจจุบัน:

```bash
npm create easy-cms@latest
```

หน้า [roadmap](/th/roadmap) บอกแต่ละระดับและสิ่งที่กำลังทำต่อ แต่ละชิ้นออกแบบใน GitHub issue ก่อนลงมือสร้าง ถ้ามีอะไรบนเส้นทางนี้ที่สำคัญกับคุณ หรือสิ่งที่คุณต้องการยังไม่อยู่บนนั้นเลย บอกผมได้ที่ [GitHub discussions](https://github.com/maritonx/easy-cms/discussions) ชิ้นถัดไปถูกเลือกจากตรงนั้น
