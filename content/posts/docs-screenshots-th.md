docs ของ Easy CMS มีภาพหน้าจอ admin อยู่ 22 หน้า รวม 35 ภาพ ทั้งฉบับไทยและอังกฤษ แต่ละภาพมีสี่แบบ: อังกฤษสว่าง อังกฤษมืด ไทยสว่าง ไทยมืด ผู้อ่านจะเห็นแบบที่ตรงกับภาษาของหน้าและธีมที่ตัวเองใช้

รวมแล้ว 120 ไฟล์ และผมไม่ได้ถ่ายเองเลยสักภาพ ทั้งหมดมาจากคำสั่งเดียว `pnpm docs:screenshots` ซึ่งเปิด admin จริงบนฐานข้อมูลที่ใช้แล้วทิ้ง ใส่เนื้อหาลงไป แล้วถ่ายภาพ บทความนี้เล่าว่าสคริปต์ทำงานอย่างไร ถ่ายฟีเจอร์ AI โดยไม่เรียก AI จริงได้อย่างไร เว็บรับภาพไปอย่างไร และอะไรที่ยังพังได้

## ทำไมไม่ถ่ายเอง

admin ที่เป็นภาษาไทยตั้งแต่วันแรกทำให้ภาพหน้าจอทุกภาพมีสองเท่า และธีมมืดคูณสองอีกรอบ หน้าจอเดียวคือสี่ภาพ และสี่ภาพนั้นต้องตรงกัน: เปิดบทความเดียวกัน เมนูเดียวกัน ตัวเลขเดียวกัน

ถ้าถ่ายเอง พอออกแบบใหม่ครั้งแรกก็ตามไม่ทันแล้ว วันที่ 30 ตุลาคม 2026 (1.25.1) admin เปลี่ยนเป็นเมนูสองคอลัมน์ และภาพทุกภาพใน docs ยังเป็นเมนูเก่า การถ่ายใหม่คือคำสั่งเดียวบวกการไล่ดูภาพใหม่ ถ้าถ่ายเองคือ 120 ภาพที่ต้องตรงกันทุกภาพ

เหตุผลข้อที่สองคือ ถ้าสคริปต์หาปุ่มจากชื่อสำหรับ accessibility ภาษาไทยไม่เจอ การถ่ายจะล้ม ทุกครั้งที่รันจึงได้ตรวจ admin ภาษาไทยไปด้วยนิดหนึ่ง เพิ่มจาก end-to-end test

## สคริปต์ทำอะไรบ้าง

สคริปต์คือ `e2e/screenshots.ts` ยาวราว 800 บรรทัด เป็น Playwright กับ `fetch` ธรรมดา รันจาก repository หลัง `pnpm build`:

```bash
pnpm build
pnpm docs:screenshots
```

![ขั้นตอนการถ่ายภาพหน้าจอ: สคริปต์ใส่ข้อมูลลงตัวอย่าง Nuxt และตัวอย่าง Next.js ที่ต่อกับ Anthropic API จำลอง ถ่ายแต่ละหน้าจอเป็นไทยและอังกฤษ สว่างและมืด แล้วเขียนไฟล์ WebP 120 ไฟล์ลง website/public/screenshots docs ใน repository ใช้ภาพจาก main ส่วน easycms.dev คัดลอกจาก commit ของ release ล่าสุดบน npm ภาพใหม่จึงยังไม่มีบนเว็บจนกว่าจะออก release ถัดไป](/images/blog/docs-screenshots/diagram-1.th.png)

**1. เปิดแอปที่ไม่มีใครใช้** สคริปต์เปิดบล็อกตัวอย่างของ Nuxt ด้วย `nuxi dev` ที่ port 3210 ใช้ไฟล์ SQLite ในโฟลเดอร์ชั่วคราว และ `EASY_CMS_SECRET` แบบสุ่ม แล้วเปิด OpenID Connect provider จำลองจาก test ของ package `auth-oauth` ด้วย หน้าจอ single sign-on จึงมีปุ่ม "Company SSO" ที่กดได้จริง พอสคริปต์จบก็ปิดทุก process และลบโฟลเดอร์ชั่วคราวทิ้ง

**2. ใส่ข้อมูลแบบที่คนใส่** request แรกสมัคร admin คนแรกผ่าน `POST /api/cms/auth/first-register` ด้วยรหัสผ่านสุ่ม ที่เหลือทั้งหมดไปทาง REST API ด้วย session นั้น: หมวดหมู่สามหมวด ภาพปก โฟลเดอร์สื่อ (มีโฟลเดอร์หนึ่งที่บาง role เท่านั้นแก้ได้) ไฟล์ CSV, PDF และไฟล์ข้อความ บทความที่เขียนเป็นไทยแล้วแปลเป็นอังกฤษ หน้าซ้อนกัน redirect ผู้ใช้ที่ได้รับเชิญแต่ยังไม่ได้ตั้งรหัสผ่าน และฟอร์มติดต่อ

รายละเอียดไม่กี่อย่างที่ทำให้ภาพดูเป็นเว็บจริง ไม่ใช่แค่ภาพหน้าจอ:

- **ภาพปกวาดเอง ไม่ได้ดาวน์โหลด** แต่ละภาพเป็น SVG ไล่สีกับรูปทรงไม่กี่ชิ้น แปลงเป็น PNG ด้วย `sharp` แล้วอัปโหลดเหมือนไฟล์ทั่วไป ไม่มีภาพ stock ไม่ต้องกังวลเรื่องลิขสิทธิ์ และเลือกสีเองได้ทุกสี
- **ฟอร์มติดต่อมีข้อมูลที่ส่งมาจริง** ส่งผ่าน endpoint สาธารณะของฟอร์มแบบที่ผู้เข้าชมส่ง และสคริปต์รอ 2.1 วินาทีก่อนส่ง เพราะฟอร์มที่ส่งภายใน 2 วินาทีหลังโหลดนับเป็นบอท ถ้าไม่รอ ด่านกันสแปมของผมเองจะทิ้งข้อมูลพวกนี้แบบเงียบๆ
- **หน้ารับคำเชิญต้องมี token** สคริปต์เซ็น token เองด้วย secret ตัวเดียวกับที่ให้ CMS หน้า "ตั้งรหัสผ่านของคุณ" จึงออกมาเหมือนที่คนได้รับเชิญเห็นจริง

**3. ถ่ายแต่ละหน้าจอสี่ครั้ง** แต่ละภาษาและธีม สคริปต์เปิด browser context ใหม่: หน้าต่าง 1440 × 900 ตั้ง `colorScheme` เป็นสว่างหรือมืด และมี init script ที่ตั้งภาษาของ admin ธีม และภาษาของเนื้อหาใน `localStorage` ก่อนหน้าโหลด จากนั้นล็อกอินแล้วไล่ถ่าย 28 หน้าจอ: dashboard รายการบทความและปฏิทิน หน้าแก้ไข แท็บ SEO ⌘K คลังสื่อ role การตั้งค่าอีเมล audit log ที่เปิดดูการเปลี่ยนแปลงไว้ หน้าล็อกอินที่มี single sign-on และอื่นๆ

ก่อนถ่ายแต่ละภาพ สคริปต์รอให้มีของบางอย่างอยู่บนหน้าก่อน ส่วนใหญ่หาจาก role และชื่อสำหรับ accessibility:

```ts
await page.getByRole('tab', { name: 'SEO' }).click()
await page.getByRole('region', { name: t.preview }).scrollIntoViewIfNeeded()
await shot('seo')
```

`t` คือพจนานุกรมเล็กๆ ภาษาละชุด เช่น `'Search result preview'` กับ `'ตัวอย่างผลการค้นหา'` หรือ `'Submissions'` กับ `'ข้อมูลที่ส่งมา'` ถ้า label ภาษาไทยเปลี่ยน หรือปุ่มไหนไม่มีชื่อ สคริปต์จะหยุดตรงนั้น

**4. บันทึกเป็น WebP** ทุกภาพรอเพิ่มอีก 400 ms ให้ animation จบ ถ่ายเป็น PNG แล้วแปลงด้วย `sharp` เป็น WebP คุณภาพ 80 ตั้งชื่อเป็น `<screen>-<locale>-<theme>.webp` ลงใน `website/public/screenshots`

## ถ่าย AI โดยไม่มี AI

มีสองหน้าจอที่แสดงฟีเจอร์ AI: หน้า Integrations ที่เชื่อม Claude แล้ว กับแท็บ SEO ของบทความหลังกด "เขียน title และ description ด้วย AI" ที่ title กับ description ที่เขียนให้อยู่ในฟอร์มแล้ว มีปุ่มเลิกทำอยู่ข้างๆ

ถ้าเรียกผู้ให้บริการจริงจะผิดทุกทาง ต้องมี key อยู่บนเครื่องผม เสียเงินทุกครั้งที่รัน และคำตอบไม่เหมือนเดิมสักครั้ง ภาพจะเปลี่ยนทุกรอบโดยไม่มีเหตุผล ภาพ AI จึงใช้ของจำลอง

`e2e/ai-mock.ts` เป็นเซิร์ฟเวอร์ Node ตัวเล็กที่พูด API ของ Anthropic เท่าที่ plugin AI ใช้: `GET /v1/models` กับ `POST /v1/messages` plugin อ่านที่อยู่จาก `ANTHROPIC_API_URL` ซึ่งค่าเริ่มต้นคือ `https://api.anthropic.com` สคริปต์แค่ชี้ไปที่ `http://localhost:3212` ตัวจำลองรับ API key ตัวเดียวคือ `sk-ant-e2e` key อื่นได้ 401 แบบที่ API จริงตอบ

คำตอบขึ้นกับ system prompt ที่ plugin ส่งมา ขอ alt text ได้ "A mountain lake at sunrise" ขอ SEO ได้ title กับ description ตายตัวเป็น JSON เป็นภาษาไทยเมื่อ system prompt ขอภาษาไทยและหน้านั้นเป็นภาษาไทย นอกนั้นเป็นอังกฤษ ส่วนการแปลจะคืนชิ้นเดิมโดยเติม `[EN]` หน้าชิ้นแรก รูปร่างที่ plugin ตรวจจึงยังเหมือนเดิม คำตอบเหมือนเดิมทุกครั้ง ภาพจึงเหมือนเดิมทุกครั้ง

ภาพ AI ยังรันบนแอปอีกตัวด้วย ตัวอย่าง Nuxt ไม่มี plugin AI สคริปต์จึงเปิดตัวอย่าง Next.js ที่ port 3211 บน PGlite ในโฟลเดอร์ชั่วคราว แล้วเชื่อมผู้ให้บริการแบบที่คนทำหนึ่งครั้งในภาษาอังกฤษ: Integrations, **Connect Anthropic (Claude)** ยอมรับนโยบายของผู้ให้บริการ พิมพ์ key กด **Find Model** เลือก "Claude E2E (claude-e2e-1)" กด **Save** แล้วตั้งเป็นการเชื่อมต่อหลัก หลังจากนั้นจึงวนตามภาษาและธีมแล้วกดปุ่ม AI

ส่วนนี้คือส่วนที่ผมชอบที่สุด ภาพของผู้ให้บริการที่เชื่อมแล้ว คือผู้ให้บริการที่เชื่อมแล้วจริงผ่าน admin จริง ไม่ใช่แถวในฐานข้อมูลที่เขียนให้ดูเหมือน และตัวจำลองเดียวกันนี้ใช้กับ end-to-end test ของ Playwright ซึ่งรันใน CI ทุก pull request ถ้า plugin เรียก API ต่างไปจากเดิม test พวกนั้นจะล้มก่อนภาพจะเก่า

## docs แสดงภาพอย่างไร

ใน repository docs เป็นเว็บ VitePress และหน้าไหนอยากได้ภาพก็เรียกตามชื่อ:

```md
<Screenshot name="forms" alt="A contact form in the admin, with its submissions panel" />
```

component ประกอบชื่อไฟล์จากภาษาของหน้าและธีมของผู้อ่าน เช่น `forms-th-dark.webp` สำหรับคนอ่านภาษาไทยในโหมดมืด และใส่ `width="1440" height="900"` หน้าจึงไม่กระตุกตอนภาพโหลด

easycms.dev เป็นโปรเจกต์ Next.js แยกต่างหาก ไม่ได้รัน VitePress แต่ render Markdown ชุดเดียวกันด้วย renderer ของตัวเอง ซึ่งเปลี่ยน `<Screenshot>` แต่ละตัวเป็นภาพสองภาพ ภาพหนึ่งแสดงในโหมดมืด อีกภาพในโหมดสว่าง หน้าแรกของเว็บก็ใช้ภาพหน้าจอบางภาพตรงๆ ในแผงที่สลับดูหน้าจอ admin ได้

## เว็บใช้ commit ของ release

นี่คือการตัดสินใจที่ทำให้เกิดปัญหาจริงอยู่ข้อเดียว

เว็บไม่เก็บ docs หรือภาพหน้าจอไว้เอง สองโฟลเดอร์นั้นอยู่ใน `.gitignore` ก่อน build ทุกครั้ง `scripts/fetch-docs.mjs` ดาวน์โหลดมาจาก repository ของ Easy CMS แต่ไม่ใช่จาก `main` มันถาม npm ว่า `@easy-cms/core` เวอร์ชันล่าสุดคืออะไร อ่าน provenance attestation ของเวอร์ชันนั้น แล้วเอา git commit ที่ใช้ build มา จากนั้นดาวน์โหลด repository ที่ commit นั้น แล้วคัดลอก `website/guide`, `website/th`, sidebar และ `website/public/screenshots`

เหตุผลคือ docs บน easycms.dev ควรบอกสิ่งที่ `npm install` ให้คุณวันนี้ ถ้าดึงจาก `main` ผู้อ่านอาจเจอ option ที่ยังไม่ออก คัดลอกไปใช้ แล้วได้ error ภาพหน้าจอก็ใช้กฎเดียวกัน ภาพจะไม่มีปุ่มที่ผู้อ่านยังไม่มี

ราคาที่ต้องจ่ายคือ อะไรที่ merge หลัง release จะยังไม่ขึ้นเว็บจนกว่าจะมี release ถัดไป สำหรับข้อความใน docs ส่วนใหญ่แบบนี้ถูกแล้ว แต่สำหรับภาพหน้าจอบางครั้งก็ไม่สะดวก

วันที่ 13 พฤศจิกายน 2026 ผมเพิ่มภาพสองภาพ คือ `ai` กับ `integrations` ครบสี่แบบ และหน้าแรกใหม่ของเว็บใช้ภาพนี้ในแผง admin ภาพทั้งสองไม่ได้อยู่ในหน้า docs ไหนเลย มีแค่หน้าแรกของเว็บที่ใช้ บน `main` ภาพมีอยู่ แต่บน commit ของ release ล่าสุดยังไม่มี จนกว่าจะมี release ที่รวมภาพนี้ build ของเว็บจะไม่มีไฟล์พวกนี้ และหน้าแรกจะชี้ไปที่ภาพที่ไม่มีอยู่ ทางแก้คือออก release: patch changeset ที่ไม่มีโค้ดเปลี่ยนเลย คำอธิบายบอกว่ามีไว้ให้เว็บได้ภาพหน้าจอ 1.46.1 ออกวันเดียวกัน

มีทางออกฉุกเฉินสำหรับเรื่องนี้ ไฟล์ `docs-ref.txt` ใน repository ของเว็บระบุ commit ที่จะใช้แทนได้ ตราบใดที่ GitHub บอกว่า commit นั้นใหม่กว่า commit ของ release พอมี release ที่รวมมันแล้ว สคริปต์จะไม่ใช้และบอกให้ลบไฟล์ เคยใช้ครั้งเดียววันที่ 17 ตุลาคม 2026 สำหรับคู่มือย้ายจาก WordPress ที่ merge หลัง 1.0.0 แล้วลบออกพร้อม 1.0.1 ในวันเดียวกัน สำหรับภาพหน้าจอผมเลือกออก release แทน เพราะการปักไว้ที่ commit จะพาการเปลี่ยนแปลง docs ที่ยังไม่ออกทุกอย่างมาด้วย

## อะไรที่ยังไม่อัตโนมัติ

ชื่อบทความเขียนว่า "คำสั่งเดียว" ไม่ใช่ "อัตโนมัติ" โดยตั้งใจ

- **ไม่มี workflow ไหนรันมัน** CI รัน end-to-end test ทุก pull request แต่ไม่รันสคริปต์ถ่ายภาพ `CONTRIBUTING.md` ขอให้รัน `pnpm docs:screenshots` หลังแก้ admin และผมรันบนเครื่องตัวเอง ถ้าลืม docs ก็จะแสดง admin รุ่นเก่าจนกว่าจะมีคนสังเกต
- **ไม่มี ADR** การตัดสินใจอยู่ใน comment ของสคริปต์ ใน `CONTRIBUTING.md` และใน `fetch-docs.mjs` ใช้ได้ตอนที่มีคนรันคนเดียว แต่ไม่พอถ้ามีหลายคน
- **ตรวจภาพด้วยตา** รันหนึ่งครั้งเขียนทับทั้ง 120 ไฟล์ บางภาพเปลี่ยนเพราะ admin เปลี่ยน บางภาพเปลี่ยนเพราะวันที่ขยับ บทความตัวอย่างลงวันที่นับจากวันนี้ ปฏิทินจึงแสดงเดือนปัจจุบันที่มีบทความเสมอ แต่ก็แปลว่าภาพปฏิทินเปลี่ยนทุกเดือน และยังไม่มี pixel diff ที่บอกว่าการเปลี่ยนไหนสำคัญ
- **ไม่ได้ตรงทุกภาพ** หน้าสาธารณะของบล็อกตัวอย่างไม่มีธีมมืด ภาพ "มืด" ของฟอร์มบนหน้าเว็บจึงดูเหมือนภาพสว่าง และภาษาหลักของเนื้อหาเป็นไทย รายการในภาพภาษาอังกฤษจึงแสดงชื่อภาษาไทย ตรงกับที่ตัวอย่างตั้งค่าไว้ แต่ผู้อ่านภาษาอังกฤษอาจแปลกใจ
- **เวลารอส่วนหนึ่งเป็นการเดา** ทุกภาพรอ element จริง แล้วรอเพิ่มอีก 400 ms ให้ transition จบ ตัวเลขนี้มาจากการลอง ไม่ได้มาจากสิ่งที่ admin บอก

## ถ้าคุณจะทำแบบนี้

ถ้า docs ของคุณมีภาพหน้าจอแอปตัวเอง สคริปต์ที่ใส่ข้อมูลแล้วถ่ายภาพจะคุ้มตั้งแต่การออกแบบใหม่ครั้งแรก ใส่ข้อมูลผ่าน API สาธารณะ ข้อมูลจะได้มีรูปร่างแบบข้อมูลจริง หา element จาก role และชื่อสำหรับ accessibility ในทุกภาษาที่มี สคริปต์จะได้ตรวจด้วยว่าชื่อพวกนั้นมีจริง จำลองบริการภายนอกที่ตอบไม่เหมือนเดิมทุกครั้ง และใช้ตัวจำลองนั้นร่วมกับ end-to-end test มันจะได้ไม่หลุดไปจากของจริงโดยไม่มีใครรู้ และตัดสินใจให้ชัดว่าเว็บดึงภาพมาจากไหน ก่อนจะต้องมาอธิบายว่าภาพหายไปไหน

ดูภาพหน้าจอได้ใน[คู่มือฟอร์ม](/th/docs/forms) [Roles](/th/docs/roles) และหน้าอื่นๆ ส่วนใหญ่ของ [docs](/th/docs) โปรเจกต์กำลังมุ่งไปเป็น backend TypeScript ทั้งตัว ซึ่งผมเขียนไว้ใน [Easy CMS ไม่ใช่แค่ CMS](/th/blog/more-than-a-cms-th) ถ้าคุณมีวิธีตรวจภาพที่เปลี่ยน 120 ภาพที่ดีกว่าการไล่ดูด้วยตา หรืออยากให้สคริปต์นี้รันใน CI มาเล่าได้ที่ [GitHub discussions](https://github.com/maritonx/easy-cms/discussions)
