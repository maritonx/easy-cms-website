Easy CMS ส่งอีเมลได้ตั้งแต่กันยายน 2026: ลิงก์ลืมรหัสผ่าน คำเชิญ การแจ้งเตือนจากฟอร์ม คำสั่งซื้อของร้านค้า และอะไรก็ตามที่โค้ดของคุณส่งด้วย `cms.sendEmail()` ตลอดช่วงนั้น วิธีส่งเป็นแค่บรรทัดหนึ่งใน config:

```ts
email: smtp({ from: 'My Site <no-reply@example.com>' }),
```

สำหรับนักพัฒนาแบบนี้ก็ใช้ได้ แต่ลองนึกถึงคนที่ดูแลเว็บอีกปีต่อมา หลังจากนักพัฒนาย้ายไปทำอย่างอื่นแล้ว ในวันที่รหัสผ่าน SMTP ใช้ไม่ได้ เขาแก้ไฟล์ config ไม่ได้ แต่เขา login หน้าแอดมินได้

ตั้งแต่ 1.42.0 เขาแก้จากตรงนั้นได้แล้ว admin เชื่อมต่อ Resend, Postmark, Brevo หรือเซิร์ฟเวอร์ SMTP ใดก็ได้ ส่งอีเมลทดสอบ แล้วเว็บก็สลับไปใช้ บทความนี้เล่าว่ามันทำงานอย่างไร การตัดสินใจเบื้องหลัง และสิ่งที่ยังทำไม่ได้

## ค่าในโค้ดยังเป็นค่าเริ่มต้น

การตัดสินใจแรกมาก่อนผู้ให้บริการเจ้าไหนทั้งนั้น: ใครชนะ โค้ดหรือแอดมิน

Settings → Backups ใน 1.41.0 เลือกทางตรงข้าม คือโค้ดชนะ admin ดูค่าได้แต่แก้ไม่ได้ สำหรับอีเมลแบบนั้นรู้สึกผิด คนที่รหัสผ่านหมดอายุคือคนที่ต้องแก้ [ADR-0066](https://github.com/maritonx/easy-cms/blob/main/docs/adr/0066-admin-overrides-code-defaults.md) จึงวางลำดับให้ทุกอย่างที่แอดมินแก้ทับได้: **ค่าที่ admin เลือก → ค่าในโค้ด → ค่าเริ่มต้นของระบบ**

```ts
import { consoleEmail, defineConfig } from '@easy-cms/core'
import { smtp, smtpProvider } from '@easy-cms/email-smtp'
import { emailPlugin, emailProviders } from '@easy-cms/plugin-email'

export default defineConfig({
  // ค่าเริ่มต้นจนกว่า admin จะเลือกผู้ให้บริการ (ไม่บังคับ)
  email: process.env.SMTP_HOST ? smtp() : consoleEmail(),
  plugins: [emailPlugin({ providers: [...emailProviders, smtpProvider] })],
})
```

`email` ในโค้ดเป็นสิ่งที่เว็บใช้จนกว่า admin จะเลือกอย่างอื่น และปุ่ม **ใช้ค่าจากโค้ด** พากลับไปได้เสมอ ใน Settings → Integrations → Email ค่าจากโค้ดแสดงเป็นการ์ดของตัวเองชื่อ **จากโค้ด** บอกว่าเป็นค่าเริ่มต้นเมื่อไม่มีผู้ให้บริการในหน้านี้ส่ง ถ้าใช้ `consoleEmail()` การ์ดนั้นจะบอกว่า `console` ซึ่งตรงไปตรงมา เพราะตอนพัฒนาไม่มีอะไรออกจากเซิร์ฟเวอร์เลย

ความตรงไปตรงมานั้นมาจากการแก้บั๊ก ก่อน 1.0.1 การส่งอีเมลทดสอบจากแอดมินตอนใช้ `consoleEmail()` จะบอกว่าส่งแล้ว ทั้งที่จริงแค่พิมพ์ลง log ของเซิร์ฟเวอร์ เว็บจริงที่ลืมตั้ง `SMTP_HOST` จึงดูเหมือนส่งอีเมลออกไปได้ จนมีคนถามว่าทำไมลิงก์รีเซ็ตรหัสผ่านไม่มาถึง ตอนนี้การทดสอบตอบ `{ "ok": true, "logged": true }` แอดมินบอกว่า **ส่งไม่สำเร็จ** พร้อมวิธีตั้ง adapter ตัวจริง และมีคำเตือนอยู่เหนือค่าที่ใช้อยู่

## ผู้ให้บริการสามเจ้า fetch สามตัว

`@easy-cms/plugin-email` เพิ่ม Resend, Postmark และ Brevo โดยไม่มี dependency ของตัวเองเลย มีแค่ `@easy-cms/core` เป็น peer ผู้ให้บริการแต่ละเจ้าคือ `fetch` ไปที่ HTTP API ของเจ้านั้น ในไฟล์ยาว 106 ถึง 137 บรรทัด

เหตุผลเหมือนที่ผมเล่าไว้ตอนทำ [ผู้ให้บริการ AI](/th/blog/ai-in-the-admin-th) Easy CMS ติดตั้งเข้าไปในแอปของคุณ dependency ของมันจึงกลายเป็น dependency ของคุณ เว็บที่ส่งด้วย Postmark ไม่ควรต้องติดตั้ง SDK ของ Resend และ Brevo ไปด้วย และส่วนของ API ที่ CMS ต้องใช้ก็มีนิดเดียว: ส่งอีเมลหนึ่งฉบับแล้วได้ id กลับมา ตรวจว่า key ใช้ได้ และอ่าน webhook

นี่คือ `send()` ของ Resend แบบตัดให้สั้น (ของจริงไม่ส่ง `cc`, `bcc`, `html` และ `text` ที่ว่าง):

```ts
const response = await fetch(`${api()}/emails`, {
  method: 'POST',
  headers: { authorization: `Bearer ${values.apiKey}`, 'content-type': 'application/json' },
  body: JSON.stringify({
    from: message.from,
    to: list(message.to),
    subject: message.subject,
    html: message.html,
    text: message.text,
  }),
})
const body = await json(response)
if (!response.ok) throw failure('Resend', response, body)
return typeof body.id === 'string' ? { id: body.id } : undefined
```

การ throw แปลว่าอีเมลจะถูกส่งใหม่ทีหลัง ผ่านคิวเดียวกับที่อีเมลทุกฉบับของ Easy CMS ใช้อยู่แล้ว: หลัง 1 นาที แล้ว 5 และ 30 นาที แล้ว 2, 6 และ 12 ชั่วโมง จากนั้นถูกทำเครื่องหมายว่าล้มเหลวใน **Settings → Deliveries** ส่วน `id` ที่คืนกลับมาเพิ่งมีใน 1.42.0 เป็นตัวที่ webhook ใช้หาอีเมลที่มันพูดถึงในภายหลัง

ข้อแลกเปลี่ยนของ `fetch` ธรรมดาคือผมต้องดูแลสิ่งที่ SDK ทำให้: ชื่อ field รูปแบบ error และรูปแบบ webhook ของแต่ละเจ้า Brevo อยากได้คนเป็น object `{ email, name }` Postmark ตอบด้วย `ErrorCode` กับ `Message` ส่วน Resend ตอบด้วย `message` ที่ทำให้จัดการได้คือการทดสอบ URL ของแต่ละเจ้าชี้ไปที่อื่นได้ (`RESEND_API_URL`, `POSTMARK_API_URL`, `BREVO_API_URL`) เทสต์ของ plugin จึงรันกับ API ปลอมขนาดเล็กของทั้งสามเจ้า และ end-to-end test ใช้หน้าแอดมินจริงกับ Resend จำลองที่รันบน port ของตัวเอง เทสต์เหล่านี้จับความผิดพลาดของผมได้ แต่จับการเปลี่ยนแปลงฝั่งผู้ให้บริการไม่ได้ ซึ่งเป็นความเสี่ยงที่ผมยอมรับ

ผู้ให้บริการไม่ได้มีแค่สามเจ้านี้ บริการไหนที่มี SMTP ใช้ผ่าน `smtpProvider` ได้ และ `defineEmailProvider()` ใน plugin ก็คือฟังก์ชันเดียวกับที่สามเจ้านี้ใช้ ถ้าอยากเขียนเจ้าที่สี่เอง

## เชื่อมต่อ แล้วพิสูจน์ให้เห็น

ในหน้าแอดมิน การเชื่อมต่อเป็นฟอร์มสั้นๆ: API key (หรือ host, user และรหัสผ่านของ SMTP) กับ **ส่งในนาม** คือผู้ส่ง ใต้ช่องเขียนไว้ว่าที่อยู่ต้องอยู่บนโดเมนที่ยืนยันกับผู้ให้บริการแล้ว

บรรทัดนั้นมีไว้เพราะเป็นทางที่พลาดบ่อยที่สุด คุณวาง key ที่ใช้ได้ ตั้งผู้ส่งเป็น `hello@yoursite.com` แล้วผู้ให้บริการปฏิเสธทุกฉบับ เพราะไม่เคยยืนยันโดเมน `yoursite.com` ในแดชบอร์ดของเขา การตรวจ key ผ่าน (Resend ตรวจ key ด้วยการขอรายชื่อโดเมน) ฟอร์มบันทึกได้ แล้วเว็บก็หยุดส่งอีเมลไปเงียบๆ

การเชื่อมต่อจึงยังไม่สลับอะไรเลย ปุ่มที่สองต่างหากที่สลับ คือ **ใช้ส่งอีเมล** ซึ่งส่งอีเมลทดสอบถึง admin ที่กด ด้วยการเชื่อมต่อนั้น key นั้น และผู้ส่งนั้น เว็บจะสลับก็ต่อเมื่อผู้ให้บริการรับอีเมลฉบับนั้น ถ้าโดเมนยังไม่ได้ยืนยัน ผู้ให้บริการจะบอกเอง admin เห็นว่าอีเมลทดสอบส่งไม่ได้ จึงไม่มีอะไรเปลี่ยน และค่าจากโค้ดยังส่งต่อไป

มีกฎอีกไม่กี่ข้อรอบๆ เรื่องนี้:

- **เฉพาะ admin ของทั้งเว็บ** ที่เลือกได้ และ audit log บันทึกว่าใครเลือก
- **การเชื่อมต่อที่กำลังส่งอยู่ลบหรือปิดไม่ได้** ต้องเลือกตัวอื่นหรือค่าจากโค้ดก่อน ไม่อย่างนั้นคลิกเดียวเว็บก็ไม่มีอีเมลเลย
- **ทุกเซิร์ฟเวอร์ตามมาเอง** การเลือกเก็บในฐานข้อมูล และแต่ละเซิร์ฟเวอร์อ่านใหม่ทุก 30 วินาที ไม่ต้อง deploy ใหม่
- **อีเมลที่รอส่งซ้ำอยู่แล้ว** จะไปกับผู้ให้บริการที่ใช้อยู่ตอนที่ถึงรอบส่งซ้ำ

## key ในฐานข้อมูล แบบเข้ารหัส

[ADR-0034](https://github.com/maritonx/easy-cms/blob/main/docs/adr/0034-admin-email-settings.md) ที่เขียนเมื่อ 4 ตุลาคม 2026 เคยปฏิเสธเรื่องนี้ตรงๆ มีคนขอแก้ค่า SMTP ในหน้าแอดมิน และผมเขียนไว้ว่าการเก็บรหัสผ่าน SMTP ในฐานข้อมูลเป็นการตัดสินใจเรื่องความปลอดภัยที่ใหญ่กว่าหน้านั้น จึงเลื่อนไปก่อน หน้านั้นทำได้แค่แสดงค่าและส่งอีเมลทดสอบ

สิ่งที่เปลี่ยนคือหน้า Integrations มาถึงก่อน (1.32.0) สำหรับผู้ให้บริการ AI และการแจ้งเตือนในแชต พร้อมคำตอบเรื่องการเก็บความลับของมันเอง ค่าที่ติดป้าย `secret` ถูกเข้ารหัสในฐานข้อมูลด้วย AES-256-GCM โดยใช้ key ที่ derive จาก `secret` ของแอป ไม่เคยส่งกลับไปที่หน้าแอดมิน ซึ่งแสดงเป็น `••••1234` และตัวแปรสภาพแวดล้อมที่ระบุไว้สำหรับ field นั้นชนะค่าที่ admin พิมพ์ หลังหมุน `secret` การเชื่อมต่อจะถูกเข้ารหัสใหม่ด้วยค่าใหม่ และ `easy-cms secrets:rotate` ทำให้ทั้งหมดในครั้งเดียว

ผู้ให้บริการอีเมลก็เป็น integration จึงได้วิธีเดียวกัน ไม่ต้องมีระบบที่สอง dump ของฐานข้อมูลอย่างเดียวไม่มี key อีเมลที่ใช้ได้ แต่ dump กับ `secret` รวมกันยังมีอยู่ ข้อนี้เลี่ยงไม่ได้ตราบที่เซิร์ฟเวอร์ต้องส่งอีเมลได้เอง

## หลังส่งไปแล้วเกิดอะไรขึ้น

การส่งเป็นแค่ครึ่งเดียว อีกครึ่งคือการรู้ว่าอีเมลไปถึงไหม

การเชื่อมต่อ Resend, Postmark และ Brevo แต่ละตัวแสดง **webhook URL** คือ `<api>/admin/integrations/resend/webhook/<token>` ให้นำไปเพิ่มที่ผู้ให้บริการพร้อม event ตามตารางนี้:

| ผู้ให้บริการ | Event | ตรวจด้วย |
|---|---|---|
| Resend | `email.delivered`, `email.bounced`, `email.complained` | token ใน URL และ signing secret (`whsec_…`) ถ้าใส่ไว้ |
| Postmark | Delivery, Bounce, Spam Complaint | token ใน URL |
| Brevo | Delivered, Hard bounce, Soft bounce, Complaint | token ใน URL |

token คือ HMAC ของ `secret` ของแอป จึงระบุการเชื่อมต่อได้และเดาไม่ได้ token ที่สร้างจาก secret เก่ายังใช้ได้หลังหมุน secret ส่วน Resend ลงลายเซ็น webhook ของตัวเอง (แบบ Svix) เมื่อวาง signing secret ไว้ request ที่ไม่มีลายเซ็นหรือเก่ากว่าห้านาทีจะถูกปฏิเสธ

![อีเมลของเว็บถูกเลือกและติดตามอย่างไร: ค่าเริ่มต้นจากโค้ด ผู้ให้บริการที่เชื่อมต่อในแอดมินพร้อม key ที่เข้ารหัสและผู้ส่งบนโดเมนที่ยืนยันแล้ว อีเมลทดสอบก่อนสลับ จากนั้นการส่ง webhook ของผู้ให้บริการ log อีเมล และรายชื่อที่ระงับ](/images/blog/email-providers/diagram-1.th.png)

แต่ละ event ทำเครื่องหมายอีเมลใน log ว่า **ถึงแล้ว**, **ตีกลับ** หรือ **ถูกแจ้งเป็นสแปม** การตีกลับที่อาจหายไปเอง เช่นกล่องจดหมายเต็ม จะไม่ถูกเก็บ ที่อยู่ที่ตีกลับถาวร หรือเจ้าของแจ้งว่าเป็นสแปม จะเข้า **รายชื่อที่ระงับ** ซึ่งแสดงเป็น **ที่อยู่ที่ระงับ** ใน Settings → Email และจะไม่ได้รับอีเมลอีก log แสดงฉบับเหล่านั้นว่าไม่ได้ส่ง admin เพิ่มและเอาที่อยู่ออกเองได้

มีข้อยกเว้นข้อหนึ่งที่ต้องคิดอยู่พักหนึ่ง คนที่กดแจ้งว่า newsletter เป็นสแปมก็ยังลืมรหัสผ่านได้ อีเมลที่คนขอเอง (รีเซ็ตรหัสผ่าน คำเชิญ ยืนยันอีเมล) จึงยังส่งถึงที่อยู่ที่เคยแจ้งสแปม แต่ไม่ส่งถึงที่อยู่ที่ตีกลับ เพราะมันรับไม่ได้อยู่แล้ว

อีกข้อที่ผมตั้งใจเลือก: ถ้าอ่านรายชื่อที่ระงับไม่ได้ อีเมลจะถูกส่งไปตามปกติและบันทึก error ไว้ การทำอีเมลรีเซ็ตรหัสผ่านหายดูแย่กว่าการส่งถึงที่อยู่ที่เคยร้องเรียนครั้งหนึ่ง

`email.bounced` และ `email.complained` เป็น system event ด้วย ถ้าใช้ `@easy-cms/plugin-notify` แชตของทีมก็ได้ยินเรื่องนี้

## log ที่ลืมเนื้อหา

ตั้งแต่ 1.41.0 Settings → Email แสดงอีเมลทุกฉบับที่ส่งใน 30 วันล่าสุด: ส่งเมื่อไร ถึงใคร หัวเรื่อง ประเภท (`password-reset`, `invite`, `form:contact`…) และผลเป็นอย่างไร ส่งแล้ว รอส่งพร้อมจำนวนครั้งที่ลอง หรือไม่ได้ส่งพร้อมเหตุผล ค้นด้วยผู้รับหรือหัวเรื่อง หรือกรองตามสถานะและประเภทได้ เห็นได้เฉพาะ admin ของทั้งเว็บ ส่วนสำเนาลับนับจำนวนแต่ไม่บอกชื่อ

log ไม่เคยเก็บว่าอีเมลเขียนว่าอะไร ลิงก์รีเซ็ตรหัสผ่านและคำเชิญพาคนเข้าระบบได้ ถ้าเก็บเนื้อหาไว้ log จะกลายเป็นรายการลิงก์เข้าระบบที่ยังใช้ได้ ส่วนการแจ้งเตือนจากฟอร์มก็มีสิ่งที่ผู้เข้าชมพิมพ์มา ราคาที่ต้องจ่ายมีจริง: คุณเห็นว่าอีเมลไปถึงใคร แต่ไม่เห็นว่าบอกอะไร และส่งซ้ำจาก log ไม่ได้ ค่าเริ่มต้นคือ 30 วัน `emailLog: { keepDays: 90 }` เก็บนานขึ้น และ `emailLog: false` ไม่เก็บเลย

เมื่อมีผู้ให้บริการแล้ว หน้านี้จึงเหลือบรรทัดสรุปบรรทัดเดียว **ส่งด้วย** Resend, **เลือกใน admin**, จากผู้ส่งของคุณ พร้อมปุ่ม **ใช้ค่าจากโค้ด** ข้างๆ ข้างใต้มีสองแท็บ: รายการอีเมล พร้อมตัวเลขฉบับที่ส่งไม่สำเร็จ ตีกลับ หรือถูกแจ้งสแปมใน 7 วัน และที่อยู่ที่ระงับ

## สิ่งที่ยังขาด

- **webhook ของ Postmark และ Brevo ไม่ได้ตรวจลายเซ็น** มีแค่ token ลับใน URL ที่ป้องกันอยู่ ใครรู้ URL นั้นก็ทำเครื่องหมายว่าอีเมลตีกลับและเติมรายชื่อที่ระงับได้ ส่วน signing secret ของ Resend ก็ไม่บังคับ
- **ผ่าน HTTP ได้แค่สามเจ้า** Amazon SES, Mailgun และเจ้าอื่นใช้ผ่าน SMTP ได้ แต่จะไม่มี event บอกผลการส่ง หรือเขียนเองด้วย `defineEmailProvider()`
- **log ไม่มีเนื้อหา** ตั้งใจให้เป็นแบบนั้น จึงไม่มีปุ่ม "ส่งอีเมลนี้อีกครั้ง" ด้วย
- **ขีดจำกัดอีเมลทดสอบ** (5 ฉบับใน 10 นาที) นับในหน่วยความจำของแต่ละเซิร์ฟเวอร์ บน serverless จึงหลวม
- **ที่เก็บไฟล์ยังสลับจากหน้าแอดมินไม่ได้** ADR-0066 เรียงการสลับเหล่านี้ตามความเสี่ยง: backup แล้วอีเมล แล้วการเข้าสู่ระบบ (ตามมาใน 1.43.0) แล้วที่เก็บไฟล์ ที่เก็บไฟล์มาท้ายสุดเพราะทุกไฟล์ต้องจำก่อนว่าตัวเองอยู่ที่เก็บไหน ไฟล์เก่าจึงยังเปิดได้หลังสลับ

## ลองใช้

```bash
npm install @easy-cms/plugin-email
```

จากนั้นเพิ่ม `emailPlugin()` แบบข้างบน สร้าง migration (`npx easy-cms migrate:create email`) แล้วเชื่อมต่อผู้ให้บริการใน Settings → Integrations → Email [คู่มืออีเมล](/th/docs/email) มีทั้ง SMTP ผู้ให้บริการ webhook และ log

ถ้าคุณใช้ผู้ให้บริการที่ไม่มีในนี้ หรือเคยเจอปัญหาอีเมลที่ระบบนี้จับไม่ได้ บอกผมใน [GitHub discussions](https://github.com/maritonx/easy-cms/discussions) และถ้ายังไม่ได้อ่าน [บทความเรื่องทิศทางของ Easy CMS](/th/blog/more-than-a-cms-th) อธิบายว่าทำไมหน้าแอดมินถึงมีสวิตช์แบบนี้มากขึ้นเรื่อยๆ
